# Сравнение Git и SVN

## 1 Почему в Git ветвление дешевое а в SVN дорогое

В Git ветка - это небольшой указатель на коммит, поэтому её создание почти мгновенно и не требует копирования файлов. Git хранит полную историю локально и умеет эффективно объединять изменения. В SVN ветка обычно представляет собой копию дерева каталогов на центральном сервере. Операции с такими ветками тяжелее, а работа слияния чаще требует ручной проверки.

## 2 Можно ли в SVN сделать коммит без интернета

Нет. SVN является централизованной системой: коммит записывается на центральный сервер, поэтому без подключения к нему создать полноценный коммит нельзя. Можно изменить файлы локально и подготовить их к отправке, но новая ревизия появится только после соединения с сервером. В Git локальный коммит можно сделать офлайн, потому что вся история репозитория хранится на компьютере разработчика.

## 3 Когда SVN может быть предпочтительнее Git

SVN может оставаться подходящим вариантом в существующих legacy-проектах, где уже настроены процессы и инструменты вокруг SVN. Он также может использоваться в организациях с очень строгой централизованной моделью доступа, когда необходимо хранить одну контролируемую копию репозитория на внутреннем сервере. Для новых командных проектов Git обычно предпочтительнее из-за удобного ветвления, офлайн-работы и современных платформ для Pull Request и Code Review.
